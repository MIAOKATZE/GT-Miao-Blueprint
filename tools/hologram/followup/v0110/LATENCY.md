## Common addon03 endpoint distinction

At runtime, the same addon detects the genuine production `HologramClient.localAreaPoint(int,int,int,int,String)` method. When absent (v019), legacy point Actions and authoritative installed-state waits remain unchanged. When present, points invoke that production local method and read `localAreaSelection()` using its real `areaPoints` coordinates. No point Action is manually transmitted in the new path. These point/cancel samples have `completionKind=clientLocal`, `firstEnvelopeNanos=0`, and `localObservedNanos/localElapsedNanos`; they are never ACK samples. The new begin still waits for real registration authority for comparability, while recording its independent synchronous local-model response. Cancel records its local completion, then separately waits for actual server cleanup before starting another round; cleanup latency is stored under `cancelAuthoritySettledElapsedNanos`.

Before the final import, the addon checks that the actual production local model has both exact corners, then calls real `worldAction(finishAreaSelection)`. The endpoint remains the installed full50k/100k authoritative product state. Begin-before-registration-ACK final intent is a separate boundary and is not claimed by this comparable case. The summary names endpoint kinds. New local response / old authoritative response is a response-path change and cannot establish a20x heavy-task or server-ACK speedup. Heavy import endpoints must be compared directly from their real runs.
