# Author source coordinate provenance

Capture handoff records the captured session's dimension and `(s.x, s.y, s.z)` as an immutable `AuthorDocument.SourceFrame`. This is the same local-to-world basis used by the existing server authoring workflow. It is **historical coordinate metadata, never world access, actor identity, or server admission authority**.

- Compact capture transfers carry `gtmbAuthorSourceFrame` in their envelope. Author admission extracts it into typed document metadata; native NBT strings are not normalized or decoded by transport/import.
- Recovery drafts store optional `sourceFrame` beside `payloadOrigins`. A world frame applies to the document; each `payloadOrigins` entry remains the cell's **local** position when its current encoded payload was produced. These are not interchangeable.
- Save/reopen, Save As, immutable editing, undo/redo, and resolved native processing retain the frame. Resolution rebases local payload origins only. Already-relative coordinate descriptors are interpreted once in that same frame, not offset a second time.
- Local inspection, processing, settlement, compilation, and explicit server compatibility review consume the same frame. Legacy explicit-coordinate compiler signatures remain available; recorded document provenance takes precedence when present.
- Files predating this metadata remain `UNKNOWN`, not falsely identified as captures at dimension 0/origin 0. Plain geometry and already-declared portable relations retain legacy compatibility. Native document operations refuse unnormalized raw world links with an actionable request to recapture instead of silently classifying/clearing them at zero. The original draft and opaque payloads remain untouched. Missing historical provenance cannot be recovered from the current player, world, or tile NBT.
- Inventory (`customPin`) samples do not inherit the destination capture frame. Newly introduced item payloads with raw world relations are refused; portable relative samples are also refused while that cell has an unresolved local payload-origin displacement. Existing retained payloads and ordinary non-coordinate samples remain compatible. Both local and explicit server configuration paths use the same guard.
- Clipboard geometry without tile/item payloads can cross frames. Opaque tile/item payloads cannot currently cross unequal frames: rejection is atomic and conservative, since the structural editor must not decode NBT to guess whether a coordinate-bearing payload is safe. Same-frame copying keeps each cell's local payload origin until explicit settlement.

Deterministic regressions cover positive/negative capture origins, dimension-sensitive hub classification, move/copy, draft recovery and history, compact transfer fidelity, repeated processing/compilation, exact absolute endpoints, safe legacy refusal, and plain-geometry clipboard compatibility.
